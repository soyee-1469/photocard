# 랜덤 포토카드 판매 서비스 기획안

> 상태: 핸드오프용 기획안 (2026-10-07)
> 대상: 디자인, 클라이언트, 서버, 운영
> 이 문서는 구현 지시가 아니다. 승인 전에 코드를 바꾸지 않는다.
> 상품 개념의 기준은 이 문서다. 화면 목업의 5대 폰 나열, 골드 버튼, 카드 앞면 선행 공개, 홀로그램 후가공은 따르지 않는다.

## 1. 한 줄 정의

앨범을 팔지 않는다. 앨범에 들어 있던 공식 포토카드만 랜덤팩으로 판다.

사용자는 앨범/시리즈 단위의 랜덤팩을 고르고 TOTT로 결제한 뒤, 그 팩에 들어 있는 포토카드 중 1장을 받는다. 받은 카드는 마이 앨범에 남고, 실물 카드로 배송된다.

## 2. 범위

### 이번 기획에 포함

- 랜덤팩 목록, 상세, 구성 확인
- TOTT 결제와 잔액 부족
- 오픈 연출과 당첨 카드 공개
- 마이 앨범 수집 현황
- 카드·앨범 커버 등록 구조
- 추첨 규칙과 희귀도
- 실물 배송이 구매의 결과라는 점

### 포함하지 않음

- 앨범 실물 판매
- 카드 표면에 입히는 디지털 홀로그램, 포일, 가짜 후가공
- 구매 전 포토카드 앞면 공개
- 선물, 거래, 중고 판매
- 배송지 입력, 송장, 배송 상태 화면. 배송은 결과로만 정의하고 화면은 아직 없다.

## 3. 용어

| 쓴다 | 쓰지 않는다 | 의미 |
|---|---|---|
| 포토카드 랜덤팩 | 앨범 상품, 앨범 뽑기 | 실제 판매 단위 |
| 수록 앨범 | 앨범 구매 | 카드가 나온 앨범. 대표 이미지는 앨범 커버 |
| 총 N종 중 랜덤 1장 | 앨범 N장 | 팩 안에 등록된 카드 수와 한 번 결제에 받는 수 |
| 포토카드 구성 | 라인업 전체 공개 | 앞면을 가린 슬롯 목록 |
| 열어보기 | 앨범 개봉 | 결제 후 카드 1장을 공개하는 연출 |

가격의 본표시는 TOTT다. 원화는 보조 문구로만 쓴다.

## 4. 상품 구조

판매 단위는 앨범이 아니라 랜덤팩이다.

```text
앨범 커버  = 어느 앨범의 카드인지 보여주는 대표 이미지
랜덤팩    = 결제하는 상품
포토카드 N종 = 그 팩 안에 등록된 실물 카드
```

예시:

```text
BLACKPINK
BORN PINK 포토카드 랜덤팩
총 12종 중 랜덤 1장
25 TOTT
≈ ₩5,000
```

팩에 12종이 있으면 시스템에는 카드 12장이 모두 등록되어 있어야 한다. 슬롯 수와 등록 수가 다르면 판매하지 않는다.

## 5. 구매 흐름

```text
랜덤팩 목록
→ 랜덤팩 상세 (구성 슬롯 포함)
→ 결제 확인
→ 25 TOTT 차감
→ 열어보기
→ 공통 오픈 연출 + 실제 카드 회전
→ 당첨 카드 공개
→ 마이 앨범 저장
→ 실물 배송
```

결제는 확인 시트를 거친다. 잔액이 가격보다 적으면 결제 버튼은 꺼지고, 차감하지 않는다. 오픈 연출은 결제가 끝난 뒤에만 시작한다.

## 6. 화면

공통 프레임은 폰 한 장이다. 화면을 나란히 보여주는 설명용 배치는 제품이 아니다.

배경 `#0B0B0D`. 본문 `#FFFFFF`. 보조 `#8A8A8F`. 카드/시트 `#151517`. 포인트는 핑크 1색이며, 결제 버튼, 선택 상태, 오픈 순간에만 쓴다. 화면 전체의 네온과 글로우는 쓰지 않는다.

내용이 폰보다 길면 화면 안에서만 내려간다. 창 바깥으로 늘어나는 세로 스크롤바는 두지 않는다.

### 6.1 랜덤팩 목록

목적: 앨범 커버로 팩을 고르게 한다. 카드 앞면은 보이지 않는다.

상단에는 화면 너비를 채우는 큰 배너를 둔다. 배너는 이번 주 추천 팩 하나다. 커버, 팩 이름, 종수, 가격이 한눈에 들어온다.

배너 아래 목록 카드:

```text
[앨범 커버]                 [뒷면 또는 작은 미공개 표시]

BLACKPINK
BORN PINK
총 12종 중 랜덤 1장
25 TOTT
≈ ₩5,000
                          [뽑기]
```

카드에 보이는 정보만 둔다.

- 앨범 커버
- 아티스트
- 앨범/시리즈명
- 총 종수와 랜덤 1장
- 25 TOTT, 필요하면 작은 `≈ ₩5,000`
- 뽑기

뽑기는 그 팩의 상세로 간다. 목록에서 바로 결제하지 않는다.

상태: 팩이 없으면 빈 목록 문구. 품절 팩은 뽑기 대신 품절을 보여 주고 상세의 결제를 막는다.

### 6.2 랜덤팩 상세

목적: 무엇을 얼마에 1장 받는지 확인하고 결제로 들어간다.

```text
[정사각 앨범 커버]

BLACKPINK
BORN PINK 포토카드 랜덤팩
총 12종 중 랜덤 1장

25 TOTT
≈ ₩5,000

[ 랜덤 포토카드 뽑기 ]
```

상단 이미지는 앨범 커버만 쓴다. 대표 카드 앞면으로 대체하지 않는다.

하단 버튼은 화면 아래에 고정한다. 라벨은 `25 TOTT · 랜덤 1장`. 잔액이 부족하면 버튼은 비활성이다.

### 6.3 포토카드 구성

상세 안의 영역이다. 별도 상품이 아니다.

12종이면 슬롯 12칸이다.

```text
포토카드 구성
총 12종

[뒷면] [뒷면] [뒷면] [뒷면]
  01     02     03     04
...
  09     10     11     12
```

구성 칸은 나올 수 있는 앞면을 자동 블러한 이미지와 번호다. 뽑은 뒤의 앞면은 원본이 아니라 워터마크가 들어간 화면용 이미지다. 물음표는 슬롯마다 넣지 않는다.

```text
랜덤으로 1장이 나와요.
```

희귀 카드가 있으면 슬롯에 등급 이름을 작게 붙일 수 있다. 앞면은 여전히 가린다.

### 6.4 결제 확인

뽑기를 누르면 아래 시트가 올라온다.

```text
랜덤 포토카드 1장을 구매하시겠어요?

BORN PINK 포토카드 랜덤팩
25 TOTT
보유 {잔액} TOTT
구매 후 {잔액 - 25} TOTT

[취소]  [구매하기]
```

취소는 시트를 닫고 상세에 남는다. 구매하기는 TOTT를 차감하고 열어보기로 간다. 차감 전에 잔액을 다시 확인한다. 그 사이 잔액이 모자라면 시트를 닫지 않고 부족 상태로 바꾼다.

### 6.5 열어보기

결제가 끝난 뒤에만 연다. 연출은 두 층이다.

```text
공통 모션 (모든 카드 재사용)
  봉투 등장 → 찢김 → 빛/파티클 → 카드 등장 → 고속 회전 → 공개 직전

실제 카드 (클라이언트 레이어)
  등록된 뒷면 → Y축 회전 → 90도에서 앞면으로 교체 → 정면 공개
```

공통 모션은 After Effects 또는 Kling으로 만들고 재사용한다. 카드가 1,000종이어도 이 모션은 하나다.

카드 앞면과 뒷면은 클라이언트에서 그린다. 뒷면이 등록되어 있으면 그 이미지를 쓴다. 공용 더미 뒷면으로 대체하지 않는다.

카드 표면은 늘리지 않고, 색을 입히지 않고, 후가공을 합성하지 않는다. 화려함은 카드 바깥의 빛과 파티클만 담당한다.

등급별로 다른 구간은 공개 직전 0.5초에서 1초뿐이다.

| 등급 | 공개 직전 |
|---|---|
| 일반 NORMAL | 고속 회전 후 감속하고 앞면을 연다 |
| 레어 RARE | 한 번 더 가속하고 빛을 퍼뜨린 뒤 앞면을 연다 |
| 스페셜 SPECIAL | 순간 정지, 짧은 암전, 강한 플래시 후 앞면을 연다 |

### 6.6 결과

연출이 끝나면 촬영한 앞면을 그대로 보여 준다.

```text
[실제 포토카드 앞면]

SPECIAL
BORN PINK
CARD 07

마이 앨범에 저장되었습니다.
```

함께 보여줄 수 있는 항목은 카드 번호, 희귀도, 아티스트, 수록 앨범, 보유 수량이다. 결과에서 마이 앨범으로 갈 수 있다.

### 6.7 마이 앨범

획득한 카드만 랜덤팩별로 모은다.

```text
BORN PINK
3 / 12
██████░░░░░░

[앞면]  [앞면]  [뒷면]
획득     획득     미획득
```

획득 칸은 앞면이다. 미획득 칸은 뒷면 또는 번호만 있는 빈 칸이다. 미획득 앞면을 보여 주지 않는다. 중복 장수를 표시할지는 아직 정하지 않았다.

## 7. 데이터

### 랜덤팩

```text
id
아티스트명
앨범/시리즈명
앨범 커버 이미지
가격 TOTT
구성 카드 수
판매 상태 (판매중 / 품절)
```

가격과 종수는 카드 목록에서 계산하지 않고 팩에 저장한다. 화면의 "총 12종"은 등록된 카드 수와 같아야 한다.

### 포토카드

```text
id                  예: BORN_PINK_01
소속 랜덤팩
앞면 이미지
뒷면 이미지
카드 번호           01–12
멤버
버전
희귀도              NORMAL | RARE | SPECIAL
재고
추첨 가중치
```

앞면, 뒷면, 앨범 커버는 서로 다른 파일이다.

### 보유

```text
사용자
포토카드 id
획득 시각
구매 id
```

한 번 결제에 카드 1장이 생긴다. 마이 앨범은 이 보유 목록으로 그린다.

## 8. 등록

실물 카드가 들어오면 순서는 고정이다.

1. 앞면 촬영 또는 스캔
2. 뒷면 촬영
3. 그 카드가 들어 있던 앨범 커버 등록
4. 랜덤팩에 카드 번호까지 연결

```text
BORN PINK 랜덤팩
→ BORN_PINK_01 … BORN_PINK_12
```

관리 화면은 이 기획의 앱 화면에 넣지 않는다. 등록 항목과 연결 규칙만 지킨다.

## 9. 추첨

결제에 성공한 순간, 그 팩의 카드 중 재고가 있는 카드만 대상으로 1장을 뽑는다.

가중치가 모두 같으면 확률은 1/N이다. 12종이면 각 1/12이다.

희귀 카드는 가중치로만 확률을 낮춘다. 희귀도는 실물 카드의 희소성이다. 한정 수량, 특별한 촬영 컷, 등장 확률의 차이다. 앱이 카드 그림 위에 등급 효과를 씌우는 기준이 아니다.

재고가 0인 카드는 추첨에서 뺀다. 재고가 있는 카드가 없으면 결제를 열지 않고 팩을 품절로 둔다.

추첨 결과, 차감 금액, 남은 잔액, 저장된 카드 id는 결제 1건에 함께 남긴다.

## 10. 가격

```text
1 TOTT = 200원
기본 포토카드 1장 ≈ 5,000원
판매가 = 25 TOTT
```

화면의 큰 가격은 `25 TOTT`다. `≈ ₩5,000`은 그 아래의 작은 글씨다. `약 5,000원`처럼 쓰지 않는다. 원화만으로 결제하지 않는다.

## 11. 디자인에 넘길 것

- 폰 한 장 기준의 목록, 상세, 결제 시트, 결과, 마이 앨범
- 목록 최상단의 큰 배너 1개
- 앨범 커버와 카드 뒷면이 구분되는 시안
- 핑크는 뽑기, 구매하기, 선택, 오픈 순간에만
- 구성 슬롯은 뒷면 + 번호. 물음표 그리드는 쓰지 않음
- 문구는 3장의 용어만 사용

## 12. 개발에 넘길 것

- 팩과 카드와 보유의 데이터 구조
- 목록에서는 커버만, 획득 후에만 앞면
- 결제 확인 후에만 차감과 추첨
- 잔액 부족이면 버튼을 끈다
- 오픈은 공통 모션 1개와 카드 이미지 2장(앞, 뒤)의 합성
- 등급 분기는 공개 직전 0.5–1초
- 종수, 슬롯 수, 등록 카드 수가 같아야 판매

현재 미리보기는 설명용이다. ARTIST A, 10 TOTT, 골드 버튼, 팩 이미지를 커버처럼 쓰는 구성은 이 기획의 화면이 아니다.

## 13. 아직 정하지 않은 것

구현하면서 채우지 말고, 정해진 뒤에 반영한다.

1. 배송지 입력 시점과 배송 상태 화면
2. 같은 카드를 다시 뽑았을 때의 표시. 마이 앨범은 획득/미획득만 정해져 있다
3. 희귀 슬롯에 등급 이름을 항상 보일지, 상세에서만 보일지
4. 목록 배너의 운영 교체 주기와 배너가 없을 때의 목록
5. 품절 팩을 목록에 남길지 숨길지
